# order-lifecycle Specification

## Purpose

订单生命周期能力：定义订单在平台内所处位置的统一状态集合、由各角色操作触发的状态推进，以及每次实际状态变化留下的可追溯日志。对应 `thesis-docs/02-需求分析.md` 的 UC-07，以及规则 R2 中「每次实际变更写入状态变更日志」的部分。

> 说明：规则 R2 中「非法迁移一律拒绝」已实施——所有状态变更统一走 `order/state.py` 的 `change_status`，由合法迁移表校验并写入状态日志（原 `_change_status` 直接赋值的实现已移除）。

## Requirements

### Requirement: 订单状态集合与初始状态

系统应当以「待支付」「已支付」「待接单」「配送中」「已完成」「已取消」「退款中」「已退款」八种状态表示订单位于生命周期中的位置，新建订单的初始状态为「待支付」。

#### Scenario: 新订单的初始状态

- **WHEN** 系统为顾客生成一笔新订单
- **THEN** 该订单的状态为「待支付」

#### Scenario: 订单完成配送后的状态

- **WHEN** 订单完成配送并被确认送达
- **THEN** 该订单的状态为「已完成」

#### Scenario: 顾客取消订单后的状态

- **WHEN** 顾客取消一笔处于可取消状态的订单
- **THEN** 该订单的状态为「已取消」

### Requirement: 配送阶段的状态推进

系统应当在骑手接单时同时把订单归属到该骑手并把订单状态推进为「配送中」，并在骑手确认送达时把订单状态推进为「已完成」。

#### Scenario: 骑手接单时记录归属

- **WHEN** 骑手对一笔尚未被接单的「待接单」订单执行接单
- **THEN** 该订单被记录为该骑手的订单，订单状态变为「配送中」，并写入一条状态变更日志

#### Scenario: 骑手标记配送中

- **WHEN** 骑手对一笔已承接的订单单独执行「标记配送中」这一操作
- **THEN** 系统拒绝并返回未知的配送状态提示——接单时订单已进入配送中，配送阶段不设中间态

#### Scenario: 骑手确认送达

- **WHEN** 骑手对本人承接的订单确认送达
- **THEN** 订单状态变为「已完成」，并记录送达时间与完成时间

### Requirement: 状态变更日志

系统应当在订单状态实际发生变化时写入一条状态变更日志，记录原状态、新状态、操作者角色与发生时间。

#### Scenario: 状态变化时写入日志

- **WHEN** 订单状态由一个取值变为另一个取值
- **THEN** 系统写入一条包含原状态、新状态与操作者角色的状态变更日志

#### Scenario: 状态未变化时不写入日志

- **WHEN** 请求把订单设置为它当前已有的状态
- **THEN** 订单状态保持原值，且不写入状态变更日志

#### Scenario: 状态变更历史可追溯

- **WHEN** 读取某笔订单的状态变更日志
- **THEN** 日志按发生先后完整反映该订单的状态变化过程

### Requirement: 状态迁移合法性

系统应当只允许订单按既定的合法迁移路径变更状态，非法迁移被拒绝，订单状态保持不变且不写入状态变更日志。

#### Scenario: 合法迁移被接受

- **WHEN** 订单按「待支付 → 已支付」「已支付 → 待接单」「待接单 → 配送中」「配送中 → 已完成」的路径变更
- **THEN** 状态变更成功并写入一条状态变更日志

#### Scenario: 拒绝状态回退

- **WHEN** 请求把一笔「配送中」的订单改回「待接单」
- **THEN** 系统拒绝并返回当前订单状态不允许该操作的提示，订单状态保持不变

#### Scenario: 配送中的订单不可取消

- **WHEN** 商户请求取消一笔「配送中」的订单
- **THEN** 系统拒绝并返回当前订单状态不允许该操作的提示，订单状态保持不变

#### Scenario: 已完成与已取消为终态

- **WHEN** 请求变更一笔「已完成」或「已取消」订单的状态
- **THEN** 系统拒绝，订单状态保持不变

#### Scenario: 目标状态不在支持范围内

- **WHEN** 请求提交的目标状态不属于系统支持的八种状态
- **THEN** 系统拒绝并返回未知的订单状态提示

### Requirement: 退款状态迁移与退款记录

系统应当在顾客申请退款时把「已支付」或「待接单」的订单推进到「退款中」，并写入一条待审核退款记录（含订单、退款金额、申请原因与申请时订单状态）；商户审核通过后订单进入「已退款」且支付记录标记为已退款，审核拒绝后订单退回申请时的原状态。「退款中」订单只能通过退款审核离开该状态。

#### Scenario: 顾客申请退款进入退款中

- **WHEN** 顾客对一笔「已支付」或「待接单」的本人订单提交退款申请
- **THEN** 订单状态变为「退款中」，并生成一条待审核的退款记录，记录退款金额与申请时订单状态

#### Scenario: 审核通过后模拟退款到账

- **WHEN** 商户对待审核的退款申请选择同意
- **THEN** 订单状态变为「已退款」，支付记录状态更新为已退款，退款记录标记为已同意并留存审核时间与备注

#### Scenario: 审核拒绝后退回原状态

- **WHEN** 商户对待审核的退款申请选择拒绝
- **THEN** 订单退回申请时的原状态（「已支付」或「待接单」），退款记录标记为已拒绝

#### Scenario: 退款审核中的订单不接受其他状态操作

- **WHEN** 对一笔「退款中」的订单请求取消、接单或其他状态变更
- **THEN** 系统拒绝，订单状态保持「退款中」，只能通过退款审核流程离开该状态
