# Spec Delta

## MODIFIED Requirements

### Requirement: 商户推进订单处理状态

系统应当允许商户更新本人店铺订单的处理状态，并允许商户取消本人店铺的订单；更新与取消都受订单状态迁移规则的约束。

#### Scenario: 更新订单状态

- **WHEN** 商户对一笔属于本人店铺且处于「已支付」状态的订单提交目标处理状态「待接单」
- **THEN** 该订单的状态更新为「待接单」，并写入一条状态变更日志

#### Scenario: 提交未知状态

- **WHEN** 商户提交的目标处理状态不在系统支持的取值范围内
- **THEN** 系统拒绝并返回未知的订单状态提示

#### Scenario: 商户取消订单

- **WHEN** 商户对一笔属于本人店铺且处于「待支付」「已支付」或「待接单」状态的订单执行取消
- **THEN** 该订单的状态变为「已取消」

#### Scenario: 拒绝不合法的状态变更

- **WHEN** 商户对一笔「配送中」的订单提交「待接单」作为目标状态
- **THEN** 系统拒绝并返回当前订单状态不允许该操作的提示，订单状态保持不变

#### Scenario: 配送中的订单不可取消

- **WHEN** 商户对一笔「配送中」的订单执行取消
- **THEN** 系统拒绝并返回当前订单状态不允许该操作的提示，订单状态保持不变

#### Scenario: 订单状态以统一的整数取值返回

- **WHEN** 商户端读取本人店铺的订单列表或订单详情
- **THEN** 订单状态以系统统一的整数取值返回，不在商户端另行映射为另一套取值
