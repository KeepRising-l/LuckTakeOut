# 项目使用文档

**项目名称：** 基于 Python 的外卖平台的管理与实现（LuckTakeOut）

**文档定位：** 系统怎么用——四端操作说明、AI 助手使用说明、答辩演示脚本与常见问题。部署与换机运行的详细步骤见 `08-部署与数据库说明.md`。

**版本：** 第 1 稿（2026-10-13）

---

## 一、快速启动（三步）

> 前提：Windows + Python 3.x + Node.js（首次使用需先按 08 文档完成一次依赖安装）。

```bat
:: ① 启动后端（终端 1）
takeout\run.bat

:: ② 构建前端（终端 2，已构建过可跳过；现场演示模式）
cd web && npm run build

:: ③ 浏览器访问
http://127.0.0.1:8091/          ← 顾客端
http://127.0.0.1:8091/merchant/ ← 商户端
http://127.0.0.1:8091/rider/    ← 骑手端
http://127.0.0.1:8091/admin/    ← 平台运营端
```

> 开发调试模式：终端 2 运行 `web\run-dev.bat`（三个 Vite 服务 5173/5174/5175 热更新，接口代理到 8091）。

**AI 助手说明：** 后端启动时会尝试从 `takeout/llm_key.txt` 读取大模型 API Key——**不配置也能用**（自动走内置规则化 Mock，演示更稳定）；已配置真实模型时走真实 LLM。两种模式下操作流程完全一致。

## 三、顾客端操作说明

| 操作 | 路径 | 说明 |
| --- | --- | --- |
| 登录 | 首页 → 登录 | 输手机号 → 点发送验证码（自动回显 `123456`）→ 登录 |
| 浏览商家 | 首页列表 | 只显示**已通过审核**的商户；展示名称/简介/评分（真实均值，无评价显示"暂无评分"）/配送费（统一 2 元） |
| 搜索 | 首页搜索框 | 按商户名或菜品名搜索（搜菜名时给出所属商户，如搜「套餐」命中川香小馆） |
| 点菜 | 进入商户 → 选菜品 | 支持分类切换；加入购物车 |
| 购物车 | 底部导航 | 修改数量、删除、合计金额（本地维护，不落库） |
| 下单 | 购物车 → 去结算 | 选择收货地址（无地址先去"我的→地址管理"新增）、填备注 → 提交订单（状态：待支付） |
| 支付 | 订单详情 → 去支付 | 模拟支付即成功（状态：已支付） |
| 订单 | 底部导航"订单" | 列表与详情；状态文案：待支付/已支付/待接单/配送中/已完成/已取消 |
| 取消 | 订单详情 | 仅"待支付"和"已支付未被接单"可取消 |
| 评价 | 订单详情（已完成） | 1–5 星 + 留言，一单一评 |
| 退款 | 订单详情（已支付/待接单） | 申请全额退款 → 商户端「退款审核」；同意模拟到账（已退款），拒绝退回原状态 |
| 地址 | 我的 → 地址管理 | 新增、删除、设默认 |
| AI 点餐助手 | 首页右下角 AI 悬浮按钮 | 点击从底部展开半屏对话面板，全程停留在首页；见第七章 |

## 四、商户端操作说明

| 操作 | 路径 | 说明 |
| --- | --- | --- |
| 注册入驻 | 登录页 → 注册 | 一步提交：账号、密码、店铺名称、电话、地址、简介 → 生成"待审核"商户 |

| 订单 | 订单管理 | 接单（已支付 → 待接单）、取消；订单的完成由骑手送达确认触发。状态由后端状态机约束 |

## 七、AI 点餐助手使用说明

**入口：** 顾客端首页右下角 AI 悬浮按钮 → 从底部展开半屏对话面板（全程停留在首页；`/ai` 为同一面板的整页版，需先登录）。

**三条使用链路（对自然语言说即可）：**

| 场景 | 示例说法 | 系统行为 |
| --- | --- | --- |
| 对话式下单 | "我想点一份川香小馆的招牌川菜套餐"（或"来份奶茶"） | 依次执行：搜索商户 → 查询菜品 → **后端校验**（价格/库存/归属）→ 生成**待确认草稿** |
| 确认下单 | 草稿卡片上点"确认下单" | 服务端把草稿转为正式订单（待支付），随后正常走支付流程 |
| 催单 | "我的单怎么还没到" | 查订单状态 → 生成催单记录 → 给商户/骑手写站内信 → 回复进度 |
| 评价 | "帮我评价一下，五星" | 定位可评价订单 → 提交评价（一单一评） |

**演示要点：** 草稿卡片会展示商户、菜品、数量、单价、总额、地址——**这些数值都来自后端重校验**，模型改不了；确认按钮是"转正式订单"的唯一入口，AI 自身没有直接下单的能力。

**连续输入：** 助手处理期间输入框不锁定，可随时补充要求（如下单后补一句"备注不要放辣椒"）；短暂停顿后的多条消息会**合并为一条**发给模型，处理为同一轮，不会遗漏也不会阻塞。

**真实性提示：** 无 Key 模式下（默认）Mock 会按关键词走向上述链路，用于稳定演示；配置真实 Key 后同一界面走真实模型推理。

## 八、答辩演示推荐脚本（3 分钟精简版）

> 打开四个浏览器标签页预置好：顾客端 / 商户端 / 骑手端 / Admin 日志页。

1. **开场（15 秒）**：一句话自述项目定位（多商户 + 受控 AI），打开顾客端首页，"这是只显示已审核商户的顾客端"。
2. **下单支付（30 秒）**：登录（任意手机号 + 123456）→ 进"川香小馆" → 加购 → 结算（选地址）→ 提交 → 支付成功。
3. **商户接单（30 秒）**：切商户端（merchant1）→ 订单管理 → 看见刚才的订单 → 接单。
4. **骑手配送（30 秒）**：切骑手端（rider1）→ 工作台看见待抢单 → 抢单 → 任务详情 → 送达；切回顾客端刷新订单 → 已完成 → 评价。
5. **AI 助手（45 秒）**：顾客端首页点右下角 AI 悬浮球，面板从底部升起 → "我想点一杯快乐奶茶的珍珠奶茶" → 展示草稿卡片（指出"金额由后端校验"）→ 确认下单。
6. **收尾（30 秒）**：切 Admin → 操作日志 → 指出刚才 **AI 的每一步工具调用都被审计**（actor_role=ai）；补一句"三个端口同源托管，`run.bat` 一条命令即可启动"。

## 九、常见问题

| 现象 | 处理 |
| --- | --- |
| 访问 8091 显示"前端尚未构建" | 先在 `web/` 执行 `npm install && npm run build` |
| AI 助手回复固定的演示话术 | 未配置 `llm_key.txt`（走 Mock），属预期行为；配真实 Key 即为真实模型 |
| 登录报"验证码错误" | 统一使用 `123456`（演示环境万能码） |
| 商户登录后只看到审核状态 | 该商户未通过审核（正常拦截）；用 `merchant1` 演示，或让运营在 Admin 里审核新商户 |
| 端口 8091 被占用 | 关闭其他占用进程，或改 `run.bat` 中的端口与前端代理配置 |
| 订单列表为空 | 先在下单流程创建订单；`seed_demo` 只建商户/菜品/骑手/顾客，**不造订单**。要连着订单演示，用 08 文档的「完整快照恢复」 |
| 想清空演示数据重新来 | 删除 `takeout/db.sqlite3` → `python manage.py migrate` → `python manage.py seed_demo` |
