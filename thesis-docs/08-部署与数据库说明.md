# 部署与数据库说明

**项目名称：** 基于 Python 的外卖平台的管理与实现（LuckTakeOut）

**文档定位：** 回答两个问题——**如何在别的电脑上快速把项目跑起来**、**数据库怎么初始化/恢复/备份**。附带的数据库脚本位于 `thesis-docs/db/`。

**版本：** 第 1 稿（2026-10-13）｜ 已在 Windows 上按本流程实际验证（含"删除数据库 → 脚本恢复"回归演练）

---

## 一、速查：新电脑三步跑起来

```bat
:: ① 后端：装依赖 → 建/恢复数据库 → 启动（终端 1）
cd takeout
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python.exe manage.py migrate          :: 方案 A：从零建库（空库+基础演示数据见下）
.venv\Scripts\python.exe manage.py seed_demo        :: 方案 A 续：写入基础演示数据（商户/菜品/骑手/顾客）

:: ② 前端：安装并构建（终端 2，只需一次）
cd web
npm install
npm run build

:: ③ 启动后端（回到终端 1）
cd ..\takeout
run.bat
```

浏览器打开 `http://127.0.0.1:8091/` 即为顾客端；商户端 `/merchant/`、骑手端 `/rider/`、运营端 `/admin/`。商户端与骑手端内部页面都是 `#` 路由（如 `/merchant/#/orders`），刷新不会 404；顾客端商家详情页是 `/shop/{id}`。

> **想连历史演示数据（订单、AI 会话）一起恢复？** 删掉/改名现有的 `takeout/db.sqlite3` 后，跳过上面的 migrate/seed，改跑：
> ```bat
> python thesis-docs\db\import_snapshot.py
> ```
> 这是完整数据库快照（详见第四章）。

## 三、首次部署完整步骤

### 3.1 获取代码

```bat
git clone <仓库地址> LuckTakeOut
cd LuckTakeOut
```

（或直接拷贝整个项目目录，注意排除 `takeout/.venv`、`web/node_modules`、`takeout/db.sqlite3` 这些本地产物。）

### 3.2 后端

```bat
cd takeout
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

`requirements.txt` 只有一行 `Django==6.1.2`（依赖极简）；若使用 MySQL，按注释再装 `mysqlclient`。

**数据库初始化（二选一）：**

| 方案 | 命令 | 结果 |
| --- | --- | --- |
| A. 从零建库 | `python manage.py migrate` + `python manage.py seed_demo` | 空库 + 基础演示数据（2 商户、5 菜品、1 骑手、测试账号）**，但订单表为空**：顾客端「我的订单」、商户端仪表盘、骑手端待抢单都没有内容 |
| B. 完整快照恢复 | 将 `thesis-docs/db/import_snapshot.py` 拷到任意位置运行（或直接 `python thesis-docs\db\import_snapshot.py`） | 完整演示数据库（含 7 笔订单、13 个 AI 会话、操作日志等历史数据） |

> **答辩用 B 方案。** `seed_demo` 只建商户/菜品/骑手/顾客，不造订单；A 方案要演示订单流程需自己先下一单。

> 快速建库快捷方式：`copy db.sqlite3 目标` —— 直接把 `takeout/db.sqlite3` 这个文件拷贝过去最省事（它在 git 里被忽略，需用 U 盘/网盘传）。

**（可选）配置真实大模型：**

```bat
:: 在 takeout\ 下新建 llm_key.txt，写入一行 API Key（该文件已被 gitignore）
:: 可另用环境变量覆盖：LLM_MODEL / LLM_BASE_URL
```

不配置也可运行——AI 助手自动走内置规则化 Mock（答辩演示推荐，更稳定）。

### 3.3 前端

```bat
cd web
npm install          :: 首次较慢，可换淘宝源：npm config set registry https://registry.npmmirror.com
npm run build        :: 三端一次构建（顾客/商户/骑手），产物由 Django 同源托管
```

> 开发调试模式（可选）：`web\run-dev.bat`，三个 Vite 服务 5173/5174/5175 热更新。

### 3.4 启动与验证

```bat
cd takeout
run.bat              :: 或 .venv\Scripts\python.exe manage.py runserver 8091
```

**部署完成检查清单（建议按序过一遍）：**

- [ ] `http://127.0.0.1:8091/` 打开顾客端首页，能看到商户列表
- [ ] 任意手机号 + 验证码 `123456` 能登录
- [ ] `http://127.0.0.1:8091/merchant/` 用 `merchant1 / merchant123` 能登录并看到数据看板
- [ ] `http://127.0.0.1:8091/rider/` 用 `rider1 / rider123` 能登录并看到待抢单列表
- [ ] `http://127.0.0.1:8091/admin/` 能打开运营后台
- [ ] AI 助手能完成一轮"对话 → 草稿 → 确认"（无 Key 时走 Mock 属正常）
- [ ] 后端自检：`python manage.py check` 无问题；`python manage.py test` 36 项全绿

### 3.5 生产部署的安全开关（可选）

开发/演示模式零配置直接运行；正式部署时通过环境变量切换为生产配置：

```bat
set DJANGO_DEBUG=0                            :: 关闭 DEBUG
set DJANGO_SECRET_KEY=<足够长的随机字符串>      :: 生产模式必须注入，未注入将拒绝启动
set DJANGO_ALLOWED_HOSTS=your-domain.com      :: 允许的主机，逗号分隔
```

配合 MySQL（见 4.3）与正式的应用服务器/反向代理即可作为生产服务部署。

## 四、数据库说明

### 4.1 默认：SQLite（零配置）

- 数据库文件：`takeout/db.sqlite3`（**已被 gitignore，不随仓库走**——这就是本目录提供 SQL 脚本与恢复脚本的原因）；
- 无需安装任何数据库服务；Django 直接读写该文件；
- 金额字段全用 `Decimal`；18 个项目迁移文件管理全部表结构（连同 Django 内置迁移共 36 条迁移记录）。

### 4.2 数据库脚本（`thesis-docs/db/`）

| 文件 | 用途 |
| --- | --- |
| `takeout_sqlite_full.sql` | **完整数据库快照**：建表语句 + 全部数据（2026-10-13 导出，含历史演示数据） |
| `import_snapshot.py` | 一键恢复：把上面的 SQL 恢复为 `takeout/db.sqlite3`（任何装了 Python 的电脑可运行，无需 Django） |
| `export_snapshot.py` | 重新导出：数据变化后刷新 `takeout_sqlite_full.sql` 快照 |

**恢复方法（等价于 import_snapshot.py 做的事）：**

```bat
cd takeout
:: 确保 db.sqlite3 不存在（先删除或改名）
python ..\thesis-docs\db\import_snapshot.py
```

**导出方法（数据更新后刷新快照）：**

```bat
python thesis-docs\db\export_snapshot.py
```

> 注意：SQL 脚本是 **SQLite 方言**，用于 SQLite 环境恢复；切换到 MySQL 时用 `migrate` 建表（见下节），不要把该脚本直接导入 MySQL。
>
> 数据安全提示：快照内含演示账号的密码哈希与示例手机号；由于是 PBKDF2 哈希（不可逆）且均为演示数据，可安全放入仓库，但请勿将真实用户数据导入后再提交。

### 4.3 切换到 MySQL 8（可选演示）

```bat
:: 1. 安装驱动（requirements.txt 里取消注释后 pip install，或直接）：
.venv\Scripts\pip install mysqlclient

:: 2. 在 MySQL 中建库：
CREATE DATABASE takeout DEFAULT CHARACTER SET utf8mb4;

:: 3. 用环境变量切换并初始化（Django 自动按迁移建表）：
set DB_ENGINE=mysql
set DB_NAME=takeout
set DB_USER=root
set DB_PASSWORD=你的密码
set DB_HOST=127.0.0.1
set DB_PORT=3306
.venv\Scripts\python.exe manage.py migrate
.venv\Scripts\python.exe manage.py seed_demo
.venv\Scripts\python.exe manage.py runserver 8091
```

### 4.4 重建数据 / 清空重来

```bat
:: 方式一：删库重来
del takeout\db.sqlite3
cd takeout && .venv\Scripts\python.exe manage.py migrate && .venv\Scripts\python.exe manage.py seed_demo

:: 方式二：恢复快照
del takeout\db.sqlite3
python thesis-docs\db\import_snapshot.py
```

## 五、数据库结构总览（业务表 25 张）

| 域 | 表 |
| --- | --- |
| 用户域 | `user_info`（顾客资料）、`user_address`（收货地址） |

## 六、常见问题（部署向）

| 现象 | 处理 |
| --- | --- |
| `pip install` 很慢 | 换源：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| `npm install` 很慢/失败 | 换源：`npm config set registry https://registry.npmmirror.com`，删除 `web/node_modules` 重装 |
| 访问 8091 报"前端尚未构建" | 未执行 `npm run build`（在 `web/` 下执行一次即可） |
| 端口 8091 被占用 | 关闭占用进程；或改 `run.bat` 端口 + `web/*/vite.config.ts` 的代理目标 |
| `manage.py` 报数据库表缺失 | 忘记了 `migrate`（方案 A）或恢复脚本（方案 B） |
| 运营端 admin 密码遗失 | `cd takeout && .venv\Scripts\python.exe manage.py createsuperuser` 重建；或在 Admin 里改密 |
| AI 助手只会固定话术 | 正常，未配置 `llm_key.txt` 时走 Mock；如需真实模型按 3.2 节配置 |
| 换了台电脑，订单/AI 历史数据没了 | db.sqlite3 不进 git；用 `import_snapshot.py` 或直接拷 `db.sqlite3` 文件 |
| 想彻底重置演示环境 | 删 `db.sqlite3` → `migrate` → `seed_demo` |

## 七、哪些文件不随仓库走（换机须知）

以下文件/目录被 gitignore，**代码仓库里没有**，换机时需要单独准备或重建：

| 文件/目录 | 说明 | 换机处理 |
| --- | --- | --- |
| `takeout/db.sqlite3` | SQLite 数据库（含全部数据） | 用 `import_snapshot.py` 恢复，或从旧机拷贝 |
| `takeout/llm_key.txt` | 大模型 API Key | 重新创建（不配置则走 Mock） |
| `takeout/.venv` | Python 虚拟环境 | 新机重新 `python -m venv .venv` |
| `web/node_modules` | npm 依赖 | 新机重新 `npm install` |
| `takeout/media/` | 上传的门店图片等 | 需要时从旧机拷贝 |
| `lucky-tackout/`、`takeout/_uidesign/` | 参考资料与设计截图（本机留存） | 与项目运行无关，无需迁移 |
