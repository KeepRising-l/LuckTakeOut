## 课题意义及要求

**意义：**

本课题旨在设计并实现一个基于 Python 的多商户外卖平台。随着移动互联网与即时配送行业的快速发展，网络订餐已成为餐饮消费的重要形态。以美团、饿了么为代表的平台本质上都是"一个平台、多方参与"的多商户系统：平台方接入并审核商户，商户维护自有菜品与订单，骑手提供配送运力，消费者跨商户浏览下单。这种业务形态对系统的数据隔离、权限控制与交易一致性提出了较高要求，是检验完整业务系统设计能力的良好载体。

本课题在实现多商户核心业务闭环（商户入驻审核、菜品管理、购物车、下单、模拟支付、订单流转、轻量配送、评价）的基础上，进一步探索大语言模型在业务系统中的安全落地问题：设计"待确认订单草稿 + 后端重校验 + 顾客确认 + 全程审计"的受控 AI 下单机制，使大语言模型在承担自然语言交互职责的同时，无法直接影响真实数据与交易安全。本课题涵盖 Web 全栈开发、数据库设计、状态机建模、认证与越权防范、大语言模型函数调用等当前主流技术，对提升工程实践能力与安全设计意识具有综合训练价值，成果可直接用于教学演示，并为中小型多商户平台开发提供参考。

**要求：**

本系统要求采用前后端分离的架构实现。后端基于 Python 语言与 Django 框架开发，提供统一格式（`{code, info, data}`）的 JSON 接口；数据库默认使用 SQLite 实现零配置运行，并支持通过环境变量切换至 MySQL 8；前端采用 Vue 3 + Vite + TypeScript 构建顾客端、商户端、骑手端三个独立单页应用，平台运营端由 Django Admin 承载；AI 能力通过大语言模型函数调用（OpenAI 兼容接口）实现，模型凭据未配置时须支持内置降级实现，保证系统随时可运行演示。

系统需完成以下核心功能：

（1）**顾客端**：手机号验证码登录；浏览已通过审核的商户与菜品；购物车管理；选择收货地址下单；模拟支付；订单列表、详情与状态跟踪；在允许范围内取消订单；收货地址管理；对已完成订单进行评价；

（2）**商户端**：注册并提交入驻申请（店铺名称、联系电话、地址、简介）；账号密码登录；查看审核状态（审核通过前不得使用经营功能）；菜品分类与菜品管理（上下架、价格与可售数量）；订单处理（接单、完成、取消）；营业信息维护与真实数据统计（订单数、营业额、营收趋势、热销菜品）；

（3）**骑手端**：账号密码登录；查看待接单列表；接单（接单即进入配送中）；确认送达；查看本人任务与今日完成单数；

（4）**平台运营端**：商户入驻审核（通过/驳回）；商户、顾客、订单查询；骑手账号维护；平台数据统计；操作日志查看（含 AI 工具调用记录）；

（5）**AI 点餐助手（创新点）**：顾客端内置，支持多轮对话收集下单信息（商户、菜品、数量、地址），由模型调用后端工具生成**待确认订单草稿**；草稿中的价格、库存与商户归属须由后端以数据库现状重新校验；顾客确认后由服务端将草稿转为正式订单并进入支付流程；支持对话式催单与辅助评价；AI 每次工具调用须写入操作审计日志，且不得存在免认证的 AI 接口。

在技术实现上，要求落实订单状态机（合法状态迁移校验与迁移日志）、四类角色独立令牌认证、服务端数据作用域隔离（防止跨商户、跨顾客、跨骑手越权）等关键机制，并以测试用例验证越权请求与非法状态迁移均被正确拦截。最终论文的撰写需完整呈现从需求分析、系统设计、编码实现到测试与部署的全过程，并提供清晰的核心代码与界面展示。

## 学生承担的任务

1. 完成多商户外卖平台的需求分析与总体方案设计（角色建模、用例分析、数据库设计）；
2. 完成后端核心业务模块的编码实现（商户入驻与审核、菜品、订单状态机、支付、配送、评价）；
3. 完成 AI 点餐助手的工具调用链路与受控下单机制（草稿单、后端重校验、操作审计）的实现；
4. 完成三端前端界面的开发与前后端联调，完成后端自动化测试与 AI 功能量化评估；
5. 完成毕业论文的撰写，并准备系统演示与毕业答辩。

## 需要的实验条件

**硬件：**

- 操作系统：Windows 11 专业版
- CPU：四核 2.0GHz 以上
- 内存：8GB 以上
- 磁盘：20GB 以上可用空间

**软件：**

- 开发语言与框架：Python 3.12、Django 6.1
- 前端环境：Node.js 22、Vue 3、Vite、TypeScript
- 数据库：SQLite（默认，零配置）；可选 MySQL 8
- 开发工具：Visual Studio Code / PyCharm、Git
- 接口测试工具：Postman / curl
- 模型服务：大语言模型对话接口（OpenAI 兼容 API，按量调用；未配置时使用内置规则化实现，保证离线可运行）
